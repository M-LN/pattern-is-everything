Why is my model not generalising?

A diagnosis in a few questions — from the gap between training and validation error to leakage and drift.

Have three numbers ready: the training error, the validation error, and — if the model is live — the error in production.
Background Bias-Variance Tradeoff · Learning Curves & Overfitting
Compare the training and validation error. What do you see?
Both are high
Use
Underfitting (high bias)

The model cannot express the pattern. Try a more flexible model, better features or weaker regularisation — and check whether the labels are too noisy to learn from.

Read Bias-Variance Tradeoff · Regularization · Feature Engineering
Training is low, validation much higher
On a learning curve, is the validation error still falling as you add data?
Yes, the gap is still closing
Use
Overfitting that more data will fix

Collect more data or augment it; until then, regularise.

Read Learning Curves & Overfitting · Regularization
No, it has flattened
Use
Overfitting from too much flexibility

Regularise, simplify, stop earlier, or prune features — more data alone will not close the gap.

Read Regularization · Bias-Variance Tradeoff · Permutation Importance
Validation looks good, but production is worse
Which of these is true?
Preprocessing was fitted on all the data, or time-ordered data were split at random
Use
Leakage

The validation score saw information the live model never gets. Fit every step inside each fold and split time series by time.

Read Cross-Validation Done Right · Cross-Validation for TS · Feature Stores
The best of many settings was picked on the validation set
Use
Selection bias (the forking paths)

The winning score was partly luck. Use nested cross-validation or a test set touched once.

Read Optuna · Cross-Validation Done Right · The Garden of Forking Paths
The live data look different from the training data
Use
Drift

Inputs, base rates or the relationship itself have moved. Monitor them and retrain on recent data.

Read Data Drift & Distribution Shift · Drift Detection in Production · Model Monitoring Dashboards
The validation score jumps between runs
Use
Noise in the measurement

A small validation set or random seeds move the score more than the change you are testing. Use repeated cross-validation and several seeds, and compare runs with a paired test.
